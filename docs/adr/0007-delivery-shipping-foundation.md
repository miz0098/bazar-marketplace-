# ADR 0007 — Phase F7 Delivery & Shipping Foundation

Status: PostgreSQL and authenticated HTTP integration foundation. Live Нова пошта/Meest transports, real tariffs, TTN/booking and tracking execution are **not enabled**. Base: merged PR #17, commit 59e7ecd1e2e1a7dfcef34c21501fd372a446b4d1.

## Evidence and provider contracts (verified 2026-10-26)

Primary sources:

- [Нова пошта integration](https://novaposhta.ua/for-business/cooperation/integration/): official HTTPS JSON entry point https://api.novaposhta.ua/v2.0/json/, business-account API key, directory/cost/tracking capabilities. [Detailed developer portal](https://developers.novaposhta.ua/) returned HTTP 403 in both browser research and the managed executor. Exact request/response schemas, warehouse-type IDs, locker restrictions and service mappings remain **unverified blockers**, not values copied from third-party SDKs or guessed from memory. No NP wire codec or outbound request is implemented. Obtain the current official schema/export and verify it with the approved account before implementing a transport.
- [Meest integration terms](https://ua.meest.com/services/shop/integration): commercial API integration requires a signed contract and manager support.
- [Meest official OpenAPI 3.0 portal](https://wiki.meest-group.com/api/ua/v3.0/openAPI), linked by its [Public API documentation](https://publicapi.meest.com/), provides [the official Swagger 2.0 schema](https://wiki.meest-group.com/api/files/openAPI_ua.json). The schema names host api.meest.com, basePath /v3.0/openAPI and a token header; citySearch, branchTypes, branchSearch, calculate and parcelStatus are documented. The pure `meest-contract.ts` subset uses actual filter/property names. `/calculate` has sender/receiver Branch service references and placesItems; `costServices` is a decimal string. It does not supply a contractual tariff-expiry timestamp or currency field. The codec converts exact decimals without float rounding and infers neither currency nor expiry. No credentials, auth token exchange or HTTP transport is constructed.
- Meest's public directory describes geo_localities and branches, public IDs and a `type=poshtomat` filter; it is not the commercial tariff API. Its documented version-1.3 change makes display branch numbers city-scoped: never use num_showcase as a global ID. Current production mapping must use the chosen API's authoritative ID. API generations are not interchangeable. Meest 3.0 branchTypes supplies type IDs; no locker UUID/weight limit is hard-coded from an example or inferred from a branch label.

Normalized BAZAR DTOs (`shipping.ts`) are **not carrier wire fields**. `revision`, `binding`, `mode`, `pickupKinds` and `expiresAt` are our integration semantics. Adapters must validate carrier status/business errors, map capabilities/types from reviewed evidence, apply real parcel restrictions and derive revision digests; a successful HTTP status alone is insufficient. Future tracking returns raw documented provider code/time only after ownership resolution; status/timeline mapping requires review. No tracking endpoint, arbitrary parcel lookup or shipment-creation method is enabled.

## Composition and truthful boundaries

Follow ADRs 0004–0006: the constructor requires NODE_ENV=test and explicit isolated-test adapters; the HTTP server rejects injection outside test configuration. Main constructs neither shipping nor test adapters. Every `/api/v1/delivery` path returns 503 in ordinary runtime. No env flag activates synthetic success. Tests/helpers is excluded from the API build. There is no new dependency, scheduled sync job, paid service or credentials variable selected by the runtime.

Both carriers have separate adapter identities; capabilities are explicit per adapter. Unsupported pickup kinds fail closed, rather than borrowing another carrier's response. Synthetic fixtures support branch only; locker search works through the same typed seam when an explicit adapter supports it, without asserting an unverified live capability. Carrier DTOs always say liveAvailable:false; ПВЗ BAZAR always says available:false. The approved UI and its provider selector remain unchanged.

The normalized adapter covers cities, city resolution, bounded point lists, single-point availability and estimates. No recipient phone, name, street/apartment, API key or caller-supplied fee is accepted. Only owned existing address IDs and public carrier/city/point references enter selection. Public branch labels are directory data, not recipient addresses. Request URLs/bodies, refs, search strings, provider payloads/errors and keys never enter structured logs. Provider failures/timeouts are sanitized; bounded cancellation has no retry/fallback or late persistence. The explicit timeout is a synthetic test policy, not an approved production SLA.

## API and checkout step 1

All successes require the existing F4 verified-session and exact same-origin protocol. POST searches also require CSRF; bodies are bounded by the existing 4 KiB/2-second parser. Unknown fields, duplicates in URL queries, client amounts/expiry, owner IDs, PII and BAZAR pickup are rejected. Static logs use `/api/v1/delivery` only.

- GET/HEAD `/api/v1/delivery/carriers`: configured isolated capabilities and unavailable BAZAR pickup.
- POST `/api/v1/delivery/cities`: `{carrier,query}`, 2–100-character search; at most 100 normalized results.
- POST `/api/v1/delivery/points`: `{carrier,cityRef,kind}`, branch/parcel-locker as supported. At most 100 results; overflow fails 503 rather than truncating. Live pagination/broad-city UX requires the approved provider contract; no invented provider cursor is introduced.
- GET/HEAD or PATCH `/api/v1/delivery/checkouts/{id}/selection`: read or select `{expectedVersion,addressId,kind}`. Owner/cart lock → checkout lock; resolve the real adapter point, verify city/kind/availability, persist selection and increment checkout version atomically. Return to payment and clear price acknowledgement/quote. A repeated or competing PATCH with the old version receives 409, never a second successful mutation.
- POST `/api/v1/delivery/checkouts/{id}/quotes`: `{expectedVersion,idempotencyKey}`. Re-read owned cart/current prices/stock/address/point and an explicit **server-owned** synthetic parcel plan; evaluate provider cost, save an immutable quote and select it atomically. Client fees/weights/origin/insurance cannot override the plan. Real catalog weight/dimensions, multi-seller origins, packaging, declared-value/insurance/COD rules are unresolved; there is no default live plan.
- POST `/api/v1/delivery/checkouts/{id}/check`: `{expectedVersion,quoteId}`. Re-read the current selected quote, cart, address, point, plan and estimate, then compare binding and expiry using fresh DB time. Return current:true only at that observation; it is not a reservation, guaranteed tariff or permission to place a real order.

Quote binding includes cart version/lines/current prices/stock, address refs, point facts/revision, plan/revision and returned estimate/revision. Changing any fact invalidates the old estimate; point removal/closure rejects availability. A newly selected quote supersedes older ones. Actor-scoped key+request digest replays the **historical estimate without extending expiry or selecting it again**; mismatched input conflicts. Explicit quoteTtlMs is required for isolated tests and labeled validitySource:integration-policy. It is not invented carrier TTL. Production freshness/quote guarantee policy must be approved separately. Cost is an estimate, not tax/insurance/COD breakdown or a payable grand total.

F6's final transaction checks for an F7 selection. If present, a shipping guard is mandatory; composing F6 without that guard cannot bypass validation. The guard checks quote freshness after F6 current pricing checks while the same owned cart/draft transaction remains locked. F6 payment-step changes do not alone invalidate shipping when bound facts are unchanged. Changing the address through the old F6 method is detected as stale; there is no alternate-address bypass. F6 order replay returns its immutable historical result, not a fresh shipping authorization. All records remain integration-test/pending, cost/payable totals null and delivery not-requested; an estimate is never silently invoiced or converted to a shipment. Existing F6 scenarios without an F7 selection remain compatible.

## PostgreSQL and concurrency

Only new migration 0007 is added. Earlier checksummed migrations remain untouched. shipping_carriers starts empty; shipping_cities and shipping_points store normalized directory observations only from explicitly configured test adapters. checkout_shipping links the owned draft/address and exact carrier/city/point/kind; shipping_quotes stores actor-scoped keys, hashes, safe integer minor-unit amount/currency, binding and explicit local validity interval. FK/unique/check constraints and indexes protect ownership/correlation and exact monetary representation. Quotes are immutable; selections on recorded checkouts are immutable. No key, phone, recipient payload, sender credentials or real tariff is seeded.

Quote advisory lock → owned cart → checkout → selection is the mutation order. Existing F5 campaign locks remain ahead of variant locks in F6; shipping reuses the cart reader and source locks. Two concurrent quotes serialize; the latest selected quote is the only accepted current one. A concurrent selection clears the previous quote. A failed quote insert or selection update rolls back the quote/key together, allowing a safe same-key retry. Provider calls occur under locks only in this bounded isolated composition; live rollout must review the obtain-outside-transaction/revalidate-and-persist protocol, idempotency and concurrency limits. No live network work is silently added to an order transaction.

## Next.js and verification

Separate typed opt-in ShippingBusinessClient uses browser-managed same-origin cookies, an explicit CSRF callback, timeout/byte limits, strict envelope/DTO/resource correlation, no redirects/cache/retries/fallback and explicit integration flags. It is never selected by demo checkout or service-provider. Real BFF/TLS/session/recipient-consent activation remains blocked. Existing approved Nova Poshta/Meest/Bazar-pickup-unavailable flow, profile, catalog and Shopify source are preserved.

Tests cover F6→F7 upgrade, fresh/repeated/concurrent migrations, both identities, supported/unsupported pickup kinds, owner/CSRF/PII/client-price rejection, point closure, expiry/tariff/package/address/price changes, key replay/mismatch, concurrent quotes/selection, rollback, final F6 guard, immutable history, provider errors/timeouts and typed client → HTTP → PostgreSQL flow. Ordinary compiled runtime rejects shipping with 503. Existing storefront, accessibility/keyboard/overflow Playwright regression remains required.
