# Full Audit Entry Criteria — Functional Candidate Gate

**Поточний стан: НЕ ГОТОВИЙ.** Ці критерії визначають передачу BAZAR на наш спільний повний аудит після функціональної розробки. Це не фінальний ручний Excel-чекліст, не дизайн sign-off і не дозвіл deployment/реальних фінансових операцій.

Профілі scope: **B** buyer-only integrated test demo; **M** full marketplace functional candidate (включає seller/admin/staff); **P** production candidate. [Визначення/рішення](REMAINING_DEVELOPMENT_ROADMAP.md). P-критерії не можна нав'язувати як вимогу реальних платежів у безпечному B demo; B pass не закриває M/P.

Всі criteria мають evidence на одному exact candidate SHA: тест/case ID, mode, actor/data namespace, expected/actual outcome, дата, owner та доступний artifact/CI. «Тип/таблиця/endpoint існує», загальна кількість tests або історичний PR не є PASS workflow.

## Умови передачі

1. Власник обирає й підписує B або M scope; required сценарії з поточного завдання не виключаються мовчки. Test adapters допустимі лише з гарантованим відділенням від production і явним simulation label.
2. Кожний applicable E01–E16 має PASS із evidence або reviewed N/A з причиною та власником. Будь-який included P0/FAIL означає **НЕ ГОТОВИЙ**, незалежно від відсотків, routes або кількості PR.
3. У buyer UI незалежний reviewer відтворює сценарії без SQL ручних правок чи підміни auth local flags. Контрольовані fictional setup/provider failures допустимі, але не замінюють сам workflow чи actor authority. Test order не стає real paid/refunded/shipped.
4. Candidate SHA і reference source/screens frozen для порівняння; дизайн не переписується. Фінальне visual/manual design приймання й оцінка screens — предмет майбутнього спільного аудиту, а не передчасний висновок F18.
5. P-перевірки/real charges/SMS/TTN/deployment потребують окремої авторизації. Проходження B/M functional gate не запускає merge, production чи платні сервіси.

## Чому зараз НЕ ГОТОВИЙ

Не виконано E01/E02/E05/E06 і included lifecycle/account/marketplace частини: ordinary mock-only storefront, неповний multi-item checkout, financial/cart-after-order/PII rules, server account/UI mapping, operational authorities, відсутні seller/admin/staff apps. F17 notification center і green CI — важливі bounded докази, але не закривають ці прогалини. Див. [пропоновані F19–F29](REMAINING_DEVELOPMENT_ROADMAP.md).
