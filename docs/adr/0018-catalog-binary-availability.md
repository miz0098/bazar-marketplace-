# ADR 0018 — F20 versioned catalog and binary variant availability

Status: implemented bounded catalog/public preview and isolated authenticated seller integration; not production readiness. Business authority: user Phase F20, BR-A04/BR-A05 in [Rules V1.1](../../BUSINESS_RULES_V1.md). Base merged PR #30 at23913f6. [Implementation, tests, bounds, routes and remaining gates](../F20_CATALOG_ACCEPTANCE.md).

Use additive migration0016 sidecars for explicitly enrolled products referencing unchanged product/variant IDs and an active seller. No fabricated seller assignment or binary availability backfill from numeric stock. Old migrations/legacy test rows remain untouched. A simple product has one canonical purchasable variant for stable cart/order identity and uses product boolean; a selectable product uses any available purchasable variant. Product/variant price and availability update via test-only real session+seller owner+Origin/CSRF/version/idempotency service, audited atomically. Seller membership is trusted fixture-provisioned, not self-granted or a full production RBAC rollout.

New reads under `/api/v1/catalog/*` use contractVersion2, actual attribute/category data, bounded literal Ukrainian search and combined filters, deterministic paging/order, publication timestamps and direct category counts. Legacy F3 `/products` and stock fields remain a deprecated technical protocol, not target availability truth. Runtime main wires public V2 reads after schema readiness, no private auth/seller adapter activation. Existing read-only DB grants must be explicitly reviewed for new tables; successful readiness is not all business permission/provider readiness.

For enrolled cart rows, checkout validates selected variant binary state and variant version without numeric quantity limits/reservation/decrement. Saved unavailable rows remain; sibling restoration does not reactivate them. Pending mixed-cart/financial/cart-completion rules are not invented. Server test checkout remains isolated; production SMS/commerce stays blocked.

A genuine restoration writes source event/audit/command and existing F13/F17 in-app notification transactionally. Variant cart recipients and product wishlist recipients obey distinct approved scopes; overlap and retries dedup, later genuine transition can notify again. Product/variant IDs retained; safe product link has no embedded credentials/PII. This does not implement consented real push or ordinary server account UI (F24/F27 gates).

Uniform prices are exact; unequal prices require variant selection, with null aggregate price. No unsupported aggregate min/first rule: price sort returns policy-required conflict for such results. Existing product layout reused, money display preserves kopecks, no fake metadata/reviews/media. Local allowlisted raster media metadata is supported but actual assets/licensing/import not supplied. Read-only `catalog-v2-preview` adapter is explicit non-production only; normal mock remains, private cart/wishlist controls disabled for that preview until F21.

Ten exact pinned Shopify footer paths now redirect308 to intent-matching routes, preserving query. Missing approved content is an explicit demo placeholder, not invented legal text/posts. Other legacy handle/source mappings remain gated. Category/model/query safety and actual regression coverage are recorded, not claimed production-scale/full design acceptance. No360° view, seller/delivery product blocks, seller/admin/staff UI, live services, merge or deployment.
