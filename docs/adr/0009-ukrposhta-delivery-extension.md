# ADR 0009 — Ukrposhta delivery extension included in Phase F8

Status: third typed carrier, isolated official-directory adapter, PostgreSQL support and demo checkout choice. No live keys, tariffs, TTN, recipient disclosure or shipment activation. Included with F8 because its PR did not exist when requested.

## Official sources verified 2026-10-26

[Ukrposhta developer documentation](https://dev.ukrposhta.ua/documentation) links:

- [Address classifier v3.22, 25.09.2026](https://dev.ukrposhta.ua/uploads/address-classifier-v3.22-25092026.pdf): HTTPS www.ukrposhta.ua/address-classifier-ws, Bearer authorization and JSON Accept header. City search uses get_city_by_region_id_and_district_id_and_city_ua with at least one documented filter; our pure builder supplies city_ua. Branch search uses get_postoffices_by_city_id with required region_id plus city_id. The normalized BAZAR city ref is an opaque region-city pair, not a claimed carrier field.
- [Domestic eCom API, 16.10.2026](https://dev.ukrposhta.ua/uploads/API_documentation_16102026_ua.pdf): POST /ecom/0.0.1/domestic/delivery-price is the calculator; W2W, addressFrom/addressTo postcode, type, validate and parcel dimensions/weight are documented fields. Calculator contract discounts/other parameters must be supplied explicitly; no test/sample price or discount is a production tariff. No default product/type, declared value, COD/fee/tax/insurance or customer discount is inferred.
- [Getting started, 11.02.2026](https://dev.ukrposhta.ua/uploads/how-to-use-api-11022026.pdf) describes Bearer eCom and user-token protection; [search guidance](https://dev.ukrposhta.ua/uploads/Search-offices-and-indexes-v3-11022026.pdf) explains offices/indices. Keys, approved account/terms and current service mappings are required before live use. Never put user tokens in logs or browser URLs.

## Implemented boundary

createUkrposhtaTestAdapter requires NODE_ENV=test and explicit isolated inputs; it has no default fetch, key, token or live estimate implementation. It builds the verified official directory URLs and validates the documented Entries.Entry shape. The server resolver retains REGION_ID/CITY_ID association; it does not invent a get-city-by-id endpoint. Branch ID comes from ID, not display text or guessed globally unique post index. Only a branch capability is advertised; no locker capability or type ID is fabricated. Unknown blocked/delivery flags remain unavailable. These are directory observations; a record alone never guarantees parcel acceptance.

The estimate seam uses an explicit synthetic test adapter; UkrposhtaCalculationRequest and the official calculator URL prepare the future wire boundary. Real deliveryPrice uses a carrier decimal representation: implement/review lossless decimal conversion, current currency, customer tariff/discount parameters and validated parcel/service mapping before an outbound calculator transport. No integer/floating tariff rounding rule or carrier TTL is invented. The inherited F7 quote engine computes only server adapter-provided integer minor units, binds owner/cart/address/point/package facts, stores explicit local test expiry and rechecks current tariff before a test order or payment preparation. There is no automatic total payable or TTN creation.

Migration 0008 expands existing named carrier CHECK constraints by adding ukrposhta; previous SQL files/checksums remain intact. It adds no live registry row or data. Existing city/point/selection/quote tables and ownership/idempotency/freshness guards are reused. F6 order snapshots/readers and opt-in checkout/shipping clients accept the third carrier. Legacy operations and the F6 prohibition on real provider writes are preserved.

The approved step-1 fieldset gains a third radio row “Укрпошта” using existing classes/layout. Its note describes a branch, not a locker. Review and session persistence preserve the selected carrier. Nova Poshta/Meest behavior and ПВЗ BAZAR disabled state remain intact. The new checkout accessibility regression exposed pre-existing sub-4.5 text/button contrast. Only checkout-scoped muted/blue shades are minimally darkened to meet contrast; layout, typography, structure and global brand tokens remain unchanged. No live search, tariff promise, profile/address UI rewrite or provider selection is enabled. Account mocks remain separate until a reviewed live mapping.

Tests cover the three carriers, official URL/shape normalization, unsupported lockers, unavailable office, changed tariff, owned selection/quote, F6 snapshot and client contracts, upgrade from F7 and desktop/mobile checkout persistence/accessibility/keyboard/overflow. No real personal data or carrier call is used.

Blockers: approved Ukrposhta Bearer/user tokens and account/contract terms; definitive service/office/parcel restrictions; server directory-region/postcode mapping and pagination/synchronization; sender location, packaging, declared value, discounts, insurance/COD/fees/tax/currency and lossless amount conversion; quote guarantee/TTL; recipient privacy/consent/retention; TTN/cancel/tracking reconciliation and release review. Production delivery remains 503, as in F7.
