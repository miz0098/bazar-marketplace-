## Умови передачі

1. Власник обирає й підписує B або M scope; required сценарії з поточного завдання не виключаються мовчки. Test adapters допустимі лише з гарантованим відділенням від production і явним simulation label.
2. Кожний applicable E01–E16 має PASS із evidence або reviewed N/A з причиною та власником. Будь-який included P0/FAIL означає **НЕ ГОТОВИЙ**, незалежно від відсотків, routes або кількості PR.
3. У buyer UI незалежний reviewer відтворює сценарії без SQL ручних правок чи підміни auth local flags. Контрольовані fictional setup/provider failures допустимі, але не замінюють сам workflow чи actor authority. Test order не стає real paid/refunded/shipped.
4. Candidate SHA і reference source/screens frozen для порівняння; дизайн не переписується. Фінальне visual/manual design приймання й оцінка screens — предмет майбутнього спільного аудиту, а не передчасний висновок F18.
5. P-перевірки/real charges/SMS/TTN/deployment потребують окремої авторизації. Проходження B/M functional gate не запускає merge, production чи платні сервіси.
