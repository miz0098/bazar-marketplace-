# BAZAR.UA — Ukraine payment and delivery compatibility (B1)

Evidence date: 2026-11-02. Requirements: **UAH, bank cards, Apple Pay, Google Pay; no COD or installments; Nova Poshta + Meest; BAZAR pickup off**. No provider is selected, installed or activated. No merchant credentials, payment/SMS/carrier operations, real orders or money tests were used.

## Evidence levels and decisive limitation

**Platform** = Shopify's documented capability/restriction. **Listing** = public Shopify App Store connector exists, with developer claims. **PSP/carrier documentation** = underlying API capability, not proof its Shopify connector exposes it. **Merchant-verified** = demonstrated in the actual BAZAR store; **none reached this level**.

Ukraine remains absent from [Shopify Payments supported countries](https://help.shopify.com/en/manual/payments/shopify-payments/supported-countries). Plus does not remove country/entity eligibility. A Ukrainian legal entity needs a supported third-party integration and provider approval; no foreign address/entity workaround is proposed.

The public `https://www.shopify.com/payment-gateways/ukraine` request returned HTTP 200 **after redirecting to the generic payment-gateways page**, not an authoritative Ukraine-filtered gateway list. Its returned HTML did not contain LiqPay/WayForPay/Portmone names. This is neither proof those gateways are unavailable nor evidence that they are merchant-enabled. Shopify directs merchants to their actual [Settings → Payments provider list](https://help.shopify.com/en/manual/payments/third-party-providers/configuring-providers), filtered by country. BAZAR admin access is unavailable, so actual store gateway availability is **blocked**, not fabricated from marketing or forum advice.

The following connector listings were read directly from Shopify App Store; forum links were used only to discover URLs, not as compatibility evidence. Listing text is supplied by developers, not an endorsement or BAZAR installation test. Its generic anonymous “not compatible” modal is not a result for BAZAR. The four connectors below are by Nabeyond Ltd/CartDNA, not proof that the underlying bank/PSP itself maintains the Shopify connector.

### Carrier API evidence and required features

The Meest public Swagger JSON was retrieved read-only (HTTP 200, 288,479 bytes, Swagger 2.0). Parsed routes document city search, branch types/search including lockers, calculation, parcel creation and tracking/status. [Evidence](analysis/shopify-plus-b1/meest-spec-evidence.json) records URL/hash/methods. **No `/auth`, `/calculate`, `/parcel`, `/tracking` or other carrier operation was called**; a specification fetch is not carrier account access. [Official Meest business documents](https://meestposhta.com.ua/for-online-shops/documents) link to the API. Repository `apps/api/src/shipping/meest-contract.ts` is a partial contract seam, not a live adapter; existing shipping scope is isolated-test. Do not reuse synthetic rates/tracking as proof.

| Required feature | Nova Poshta | Meest | Required implementation/proof |
|---|---|---|---|
| City selection | Apps claim directory/warehouse selection; exact city UX untested | Public `/citySearch` documented | Stable canonical city ID, Ukrainian labels/search, pagination/cache and current coverage; not arbitrary client string. |
| Branch selection | Service/Connect listings cover warehouse/branch | `/branchSearch` + `/branchTypes` documented | City/point consistency, availability, weight/size restrictions and normalized address persisted before payment. |
| Locker selection | Connect explicitly advertises lockers; Service listing alone not sufficient | Branch-type/search spec includes lockers | Confirm each merchant contract/point supports chosen parcel and delivery kind; no automatic fallback to wrong branch. |
| Delivery method | Branch/locker/courier options in Connect | Branch/locker/address modes need contract mapping | Expose only approved eligible methods per seller and avoid confusing carrier pickup with BAZAR pickup. |
| Shipping cost | Service advertises calculated rates and CCS | `/calculate` documented | Actual origin/package/declared value/contract/payer/tax, timeout, freshness and seller aggregation; unknown does not equal free. |
| Tracking number | TTN creation advertised | `/parcel` documented | Idempotent actual waybill creation after allowed order/payment state; never generate fake TTN or claim shipped before carrier fact. |
| Delivery status | Listings advertise sync | `/parcelStatus/{parcelID}` and `/tracking/{trackNumber}` documented | Authenticated API polling or verified event mechanism, dedupe, time ordering and truthful pending/unknown states. |

A checkout extension only renders/collects selection. The independent backend validates real directory IDs and parcel eligibility; persistent order/cart metadata preserves canonical carrier, city, branch/locker and version/snapshot for each delivery group. Direct/express checkout must reject a missing/stale/tampered selection using supported server validation, not only frontend navigation interception. A signed server-issued selection reference may be appropriate but must fit actual Function input/network constraints; the signature/validation mechanism must be proven, not assumed.

CarrierService returns rates, **not city/branch UI**, and needs `write_shipping` plus eligible actual store entitlement. Plus should qualify once activated, but is unverified. [API 2026-10 no longer auto-attaches new carrier services to General shipping profiles/zones](https://shopify.dev/changelog/posts/carrier-services-will-no-longer-be-automatically-added-to-the-default-shipping-profile); configure intentionally in later authorized development work. Delivery Customization hides/renames/sorts existing rates, not a replacement carrier tariff engine. Approve whether shipping is paid at checkout or to carrier and how the screenshot's “carrier tariff” wording maps to an exact Shopify payable total.

Preserve independent backend/admin/CRM; use seller-origin/fulfillment mapping without moving their interfaces into Shopify. Avoid two apps creating waybills for the same order. One app/worker owns each carrier shipment operation. BAZAR local pickup remains disabled in configuration and validation. Existing Ukrposhta source is preserved but excluded from the approved delivery choices. COD automations and installment methods remain off.
