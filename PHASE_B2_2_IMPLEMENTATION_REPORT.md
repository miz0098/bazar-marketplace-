## Implemented components

- Collection catalog: actual title/count; configured three-level category navigation, active collection and ancestor breadcrumbs; accessible collapsible category/filter panel; real Shopify list/boolean/price facets and selected-removal links; supported sort options; finite numbered pagination and empty state.
- Product cards: real images/escaped titles/product links; configured presentment currency through Shopify money filters; varying-price minimum; same-variant compare-at and calculated percentage only for a single variant; availability; pending favorites icon; eligible quick add or explicit product-page selection.
- Collections index: actual Shopify `collections`, 24 per page, real collection images/titles/URLs and empty state. It replaces the active generic English composition through a reversible section mode, without importing a fictional taxonomy. Category-card anatomy is reference-based; a dedicated final index composition is missing.
- Search compatibility: the same canonical Horizon card renderer supports BAZAR content in native search results. Native search query parsing, facets, sorting, result selection and predictive search stay intact. Search uses finite native pagination. No new index/backend/history or replacement autocomplete.
- B2.1 header/footer/home/tokens/settings are preserved. One necessary header correction adds `aria-label="Каталог"` because its text is hidden on mobile. New collection root `.bazar-collection` avoids colliding with the header's existing `.bazar-catalog`.

## Shopify objects and architecture

**One card rendering entry point:** keep `blocks/_product-card.liquid` → `snippets/product-card.liquid` and its native custom-element shell, event payload, settings and default branch. BAZAR is an opt-in section mode selected in collection/search JSON; its content helper is not a second product-card system. The old source `bazar-product-card.liquid` is **not imported**. Native child-block settings/data remain intact for Horizon mode; editor paragraphs explain that the BAZAR card has a fixed composition. Native editor block placement/rendering still requires merchant validation.

`collection.products` is inside Shopify `paginate`, using the section's 8–36 products/page control (24 selected). In BAZAR mode pagination is always finite; the native infinite-scroll control applies to Horizon mode. Category hierarchy is **merchant menu structure**, not an inferred Shopify parent relationship. Breadcrumb ancestors come from the first matching configured menu path, up to three levels; without a matching path only Home/current collection appears. Select the same genuine taxonomy/menu deliberately; no automatic menu or collection creation.

`collection.filters` supplies `type`, labels, values/counts, active values, parameter names, min/max/range and removal URLs. No unsupported brand/category/metafield facet is invented. Merchants must configure available definitions/data through Shopify/Search & Discovery separately. Standard `list`, `boolean`, `price_range` are rendered; future unknown types are not synthesized. Price inputs use Shopify monetary values divided by `100.0` as numeric major-unit URL values, avoiding localized grouping/decimal strings. Actual currencies/Markets require merchant testing.

Filter controls and external sort select/submit share **one GET form** through HTML's `form` attribute. This preserves checked facets and price boundaries without nested product forms or duplicated hidden lists. If filter UI is disabled, existing active values are retained as hidden controls. Changing filters/sort omits the old page parameter. Selected removal and pagination use Shopify-provided URLs; reset clears facets while keeping the actual selected sort. Search continues to use native Horizon query/facet machinery, including `q`/prefix parameters. Its complete UI/localization is not restored here.

Quick add is eligible only for **one total variant**, `variant.available`, no required selling plan, no minimum/increment greater than one, and no configured volume-price breaks. Other purchasable products lead to the real product URL for selection; unavailable products have no add form. Optional app-required line properties/customizable bundles are not inferable from arbitrary Liquid flags: validate merchant apps/catalog before enabling this theme, and extend eligibility in a separately reviewed change where necessary. No production bundle integration is claimed.

The real Shopify product form provides the non-JavaScript POST fallback. The isolated `bazar-card-form` enhancement uses `Theme.routes.cart_add_url`, exact variant ID/quantity 1, same-origin cookies and bundled section requests (maximum five), then fetches authoritative cart JSON. Only confirmed responses update the existing Horizon cart icon/drawer/items through `CartLinesUpdateEvent`. No optimistic count, fake animation, auth flags or local wishlist ownership. Pending submission is locked; a known rejection shows safe text and permits retry. An unknown POST outcome or failed post-add cart refresh stays locked with a cart link until navigation/reload; there is **no automatic POST retry**, since Ajax cart offers no assumed request-idempotency guarantee. Server rejection remains authoritative. Full native drawer morphing and concurrent-cart races need live-store validation.
