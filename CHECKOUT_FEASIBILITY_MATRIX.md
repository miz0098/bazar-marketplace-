# BAZAR.UA — Shopify Plus checkout feasibility matrix

Date: 2026-11-02. Platform documentation reviewed; **no merchant checkout tested**. Plus is the selected target, not a verified active subscription. Approved source: [Checkout Desktop v1.0 (FINAL).PNG](design-reference/storefront/Checkout%20Desktop%20v1.0%20%28FINAL%29.PNG), visually re-inspected for B1. It shows contacts/delivery, payment and confirmation as a three-panel design board, not three simultaneous columns to render.

## Mechanisms and their limits

- [Checkout UI Extensions](https://shopify.dev/docs/api/checkout-ui-extensions/latest): Plus information/shipping/payment targets and platform UI components; no arbitrary host DOM/CSS, no replacement secure payment form. Extension rendering is constrained to supported targets and capabilities.
- [Checkout Branding API](https://shopify.dev/docs/api/admin-graphql/latest/objects/CheckoutBranding): brand colors, typography, corner/section/control styling and permitted layout settings. It cannot reconstruct arbitrary theme layout or field order. Also assess the newer [Checkout and Accounts Configuration API](https://shopify.dev/docs/apps/build/checkout/styling/checkout-and-accounts-configuration) for a shared configuration, with supported schema/scopes; do not mix independent mutations without clear ownership. API 2026-10 is the B1 documentation baseline, not a validated BAZAR deployment version.
- [Shopify Functions](https://shopify.dev/docs/api/functions/latest): backend validations/discounts/delivery/payment logic, not a UI renderer, live SMS service, payment gateway or shipping-rate provider. Custom-app Function entitlements and schema must be verified. Never assume unrestricted network requests are available inside a Function; use supported inputs/configuration and an approved architecture.
- [Delivery Customization](https://shopify.dev/docs/api/functions/latest/delivery-customization): hide/rename/order existing options, not calculate arbitrary carrier quotes or draw city/branch selectors.
- [Payment Customization](https://shopify.dev/docs/api/functions/latest/payment-customization): adjust supported methods, not implement card processing. Wallet names/logos cannot be renamed; wallets cannot be reordered, though removal is supported under documented conditions. Shop Pay has separate restrictions. A Function cannot remove installments nested inside a redirected PSP page.
- Thank-you uses appropriate checkout extension targets; current order-status uses customer-account extension targets. [Customer-account extensions](https://shopify.dev/docs/api/customer-account-ui-extensions/latest) are a separate runtime from the Liquid theme; source and styling are not interchangeable.

## Requirement matrix

“Conditional” means supported mechanism exists but store/connector/business proof is missing. “Partial” means a material visual/flow difference is expected. “No” applies to the exact requirement, not to selling through Shopify.

## Material deviation register

D1: step topology; D2: native header/footer; D3: platform typography/spacing/layout bounds; D4: mandatory verified-email enrollment for A; D5: native contact/address fields and validation; D6: branch-selector placement/native delivery UI; D7: wallet buttons/eligibility/redirect; D8: native discounts/summary/pay action/mobile collapse; D9: disabled COD/pickup placeholders omitted or supplemental; D10: paid/TTN/ETA and multi-seller confirmation states; D11: hosted current-account routing/shell; D12: accessible native responsive behavior differs from unresolved theme grids. Each row above records the corresponding proof; none is accepted merely by selecting Plus. No broad claim of pixel-perfect checkout is justified.

## Recommended B2 proof

Use the native layout that product approves after side-by-side review; do not select one silently. In an explicitly authorized Plus-enabled development store, first add a **non-transactional** block at a supported target and validate branding/scopes/API version. Inspect pre-payment city/branch behavior, native versus redirected payment UI and account continuity. Capture actual desktop/mobile deviations and block invalid direct/accelerated paths. Use local/provider test mode only within the scope then approved. A mock extension render or CLI build does not prove payment, carrier or account integration.

Shopify's [native layout documentation](https://help.shopify.com/en/manual/checkout-settings/customize-checkout-configurations/one-page-checkout) and [checkout.liquid deprecation](https://shopify.dev/docs/storefronts/themes/architecture/layouts/checkout-liquid) rule out promising the reference through arbitrary Liquid. CLI is absent here; no CLI scaffold/build, store rendering, branding mutation, Function execution or extension deployment was performed. Local OIDC/configuration experiments are described separately and do not prove this matrix.
