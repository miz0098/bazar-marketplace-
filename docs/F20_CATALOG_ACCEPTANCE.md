No existing record/ID is deleted or assigned a fabricated seller. Old migrations0001–0015 remain byte-identical. A published simple product must have one canonical purchasable variant; selectable products at least one. Old `/api/v1/products` is the frozen F3 numeric-stock/min-price protocol; consumers must not use it as the V2 availability contract. New catalog never reads stock to infer availability. Legacy test rows remain legacy; explicit enrollment/import and least-privilege new table grants require a reviewed operator process. No import or production activation is claimed.

No public self-grant, seller registration or publication dashboard.
- Existing cart repository and checkout snapshot seam check V2 binary state for enrolled rows and preserve legacy behavior for unenrolled rows. Quantities are purchase units, not inventory: stock=0 does not block an available V2 variant, while unavailable selected variant is rejected even if a sibling is available. Full multi-seller financial checkout remains F22.
- Restored availability writes a source event and F13/F17 in-app inbox records atomically with audit/receipt. Product and variant event scopes preserve product/variant IDs. Recipient union uses saved wishlist product transitions fully-unavailable→available and cart selected-variant transitions; cart+wishlist overlap receives one notice for the same source transition. Retry replays historical receipt; a later genuine restoration creates a new event. Recipients are ordered by UUID for existing inbox locks. No push transport, consent default or production sender enabled; existing inbox mode remains integration-test. F24: ordinary server-account/inbox integration and preferences; F25: genuine seller runtime; F27: consented outbound channels.
- Public V2 queries: case-insensitive literal substring title+stored approved attribute values (including brand if present), category subtree, brand, one attribute key/value pair, availability and integer price bounds together; allowlisted default/newest/name/price ordering, deterministic ID ties, page1..10000/size1..100 and exact total.
